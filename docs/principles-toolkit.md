## 4. 회의 중 실시간 메모 (`/meetings` 첫 번째 탭)

"회의록을 공용 화면에 띄우고 마크 달기 / 말하면 적히는 메모·트리형 / 누가·무엇을 워크플로우 / 공유"를 한 화면에 넣었습니다.

**트리형 아웃라이너**
- `Enter` 새 줄 · `Tab` 들여쓰기 (최대 5단계, 직전 줄보다 깊게는 안 됨) · `Shift+Tab` 내어쓰기
- 빈 줄에서 `Backspace` → 줄 삭제하고 위로 이동 · `↑↓` 줄 이동
- 1.2초 디바운스 자동 저장, 페이지 이탈 시에도 저장

**마크 (Ctrl+1~4 또는 좌측 버튼 클릭으로 순환)**

| 키 | 마크 | 산출물에서 |
|---|---|---|
| Ctrl+1 | ★ 중요 | "중요 표시" 섹션 |
| Ctrl+2 | ◆ 결정 | "결정된 것" 섹션 |
| Ctrl+3 | ☑ 할 일 | "할 일" 표 + 칸반 전송 대상 |
| Ctrl+4 | ❓ 확인 필요 | "확인이 필요한 것" 섹션 |

**누가 · 무엇을 · 언제까지** — 할 일로 표시하면 담당·기한 칸이 그 줄에 바로 나타남.
`☑ 할 일 → 칸반 카드` 로 보내면 기한 있는 건 '즉시처리', 없는 건 '전략적계획'으로 들어감.

**받아쓰기** — Web Speech API(Chrome). 말하면 새 줄로 쌓이고, 마크는 나중에 붙이면 됨.

**발표 모드** — 공용 화면에 띄울 때 글씨를 키우고 메타 영역을 흐리게. 상태는 브라우저에 기억.

**공유** — 결정/할 일/확인 필요만 뽑아 카카오 공유 또는 클립보드 복사.

**회의록으로 확정 저장** — `meetings` 테이블에 md로 저장(재저장 시 갱신). 기존 회의록 목록·읽음 처리와 그대로 연결.

## 5. 산출물 포맷 고정 (md → html → PDF)

`src/notedoc.ts` — `noteToMd()` / `noteToHtml()`.
**"목적을 알 수 있게 상세히"** 요구를 구조로 고정했습니다: 제목 바로 아래에
**"이 회의로 정하려는 것"** 블록이 항상 오고, 비어 있으면
_"목적이 적히지 않았습니다 — 다음 회의에는 먼저 적어주세요"_ 가 대신 찍힙니다.

고정 순서: 제목 → 목적 → 메타(날짜·참석·기록) → 결정된 것 → 할 일 표 → 확인 필요 → 중요 → 메모 전문(트리 그대로)

- `GET /api/notes/:id/export?fmt=md` — md 내려받기
- `GET /api/notes/:id/export?fmt=html` — html 내려받기
- `?fmt=html&inline=1` — 새 탭에서 열기 → **브라우저 인쇄로 PDF 저장**
  (`@media print` + `@page margin:16mm` + `print-color-adjust:exact` 로 색·마크가 인쇄에도 남음)

서버 PDF 생성은 Workers에서 무거워 넣지 않았습니다. 인쇄 경로가 실질적으로 같은 결과를 냅니다.

## 6. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/notes` | 내 메모 목록 (할 일 개수·확정 여부 포함) |
| GET/POST/PUT/DELETE | `/api/notes[/:id]` | 메모 CRUD |
| POST | `/api/notes/:id/kanban` | 할 일 → 칸반 카드 |
| POST | `/api/notes/:id/publish` | 회의록(meetings)으로 확정 |
| GET | `/api/notes/:id/export?fmt=md\|html` | 산출물 내보내기 |

`cleanOutline()`으로 서버에서 깊이(0~5)·마크 화이트리스트·길이(줄 1000자, 500줄)를 강제합니다.

## 7. 검증 (실제로 한 것)

1. `npx tsc --noEmit` 통과 · 모든 인라인/외부 JS 문법 검사
2. **Playwright 실제 브라우저 12항목 시나리오 전부 통과** — 배너, 아코디언 7개,
   2중 아코디언 4섹션, 시각별 자동 펼침, 체크리스트 21개, 원칙→카드 이동,
   기본 탭, Ctrl+2 마크, Tab 들여쓰기, 할 일 칸 노출, 자동 저장, 주차 라벨
3. 트리 입력 → 새로고침 → 복원(5줄·목적 유지) 확인
4. 칸반 전송 1건 생성 확인 · 회의록 확정 후 목록에 뜨는 것 확인
5. 내보낸 html을 **실제로 열어 렌더 확인 + PDF로 인쇄해 이미지로 육안 확인**
6. 데스크톱/모바일(420px) 6개 화면 가로 넘침 0
7. 콘솔 SQL을 신규 DB에 적용 + 3회 재실행해 멱등성 확인

**잡은 회귀 1건**: 3원칙 앵커용으로 카드에 `id="week"`를 붙였는데 내부 그리드와 **id가 겹쳐**
주간 스케줄 카드가 통째로 덮어써졌습니다. Playwright 검사에서 "아코디언 7개" 항목이
6개로 나와 발견 → `id="weekcard"`로 분리해 수정.
