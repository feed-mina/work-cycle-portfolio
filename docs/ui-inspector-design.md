# UI 인스펙터 — 설계

작성: 2026-08-23 / 대상: work-cycle + 사내 웹 프로젝트 전체

## 1. 목적

화면을 보며 "여기 이게 이상해요"라고 말할 때, **어디를 말하는지 정확히 남긴다.**

지금은 스크린샷에 빨간 네모를 그려 슬랙에 올린다. 받는 쪽은 그 네모가 어느
요소인지 다시 찾아야 하고, 화면이 바뀌면 그 스크린샷은 무엇을 가리켰는지 알 수 없게 된다.

인스펙터는 **살아 있는 화면에서** 요소를 클릭해 댓글을 단다. 그래서 좌표가 아니라
**요소 자체**가 남는다.

> `docs/업무습관도구-실행플랜.md` §6의 "화면 댓글 리뷰 도구(③)"를 대체한다.
> 그 계획은 **스크린샷 이미지**에 핀을 찍는 것이었다. 이쪽이 상위 호환이다 —
> 스크린샷으로는 요소 경로·화면 너비·브라우저를 얻을 수 없다.

## 2. 가장 중요한 제약: 여러 프로젝트에 붙어야 한다

`work-cycle` 전용이면 의미가 없다. `feed-mina.github.io`, `ask-todo-hub`,
`sdui-template-kit-productization` 등에서 **똑같이** 동작해야 한다.

| 방식 | 프로젝트 코드 수정 | 적용 범위 | 배포 |
|---|---|---|---|
| **북마클릿** | **불필요** | 로컬·스테이징·운영 전부. 로그인 뒤 화면도 됨 | 파일 하나 교체 |
| 브라우저 확장 | 불필요 | 더 강력하나 스토어 심사 또는 개발자모드 설치 | 사람마다 재설치 |
| `<script>` 삽입 | **프로젝트마다 필요** | 넣은 곳만 | 프로젝트마다 배포 |

**북마클릿으로 간다.** 주소가 `javascript:` 로 시작하는 북마크로, 아무 페이지에서나
누르면 그 페이지에 인스펙터가 얹힌다. 공유는 "이 링크를 북마크바로 끌어다 놓으세요" 한 줄.

확장으로 갈 이유가 생기면(예: 스크린샷 캡처가 꼭 필요해짐) 그때 승격한다.
수집·저장 규약은 그대로 쓸 수 있게 설계한다.

## 3. 새로 만들지 않는다 — Pinment 포크

설계를 마친 뒤 기존 도구를 조사했더니 **거의 같은 것이 이미 있었다.**
직접 확인한 결과(2026-08-23 기준):

| 저장소 | 형태 | 라이선스 | ★ | 쓸 수 있나 |
|---|---|---|---|---|
| **khawkins98/pinment** | 북마클릿 | MIT | 3 | **포크 대상** |
| wernerstrauch/visual-annotator | Chrome 확장 | MIT | 4 | **UI 코드를 가져온다** (도구로는 도입 안 함) |
| aranticlabs/bugpin | 자체 서버 + 위젯 | 위젯 MIT / 서버 **AGPL-3.0** | 29 | M2 때 검토 |
| benjitaylor/agentation | React 컴포넌트 | **PolyForm Shield** | 4,400 | **못 쓴다** |
| botanicastudios/element-selector | DOM 선택 라이브러리 | MIT | 0 | 부품 후보 |

### 별 개수를 그대로 믿으면 안 된다

**목록에서 유일하게 널리 쓰이는 것(Agentation, ★4,400)이 유일하게 못 쓰는 것이다.**
PolyForm Shield는 오픈소스 라이선스가 아니고, React 18+ 전용이라 프레임워크 중립이라는
전제도 깨진다.

나머지는 전부 ★0~29다. **"이미 검증된 코드"가 아니라 "먼저 만들어 본 사람이 있다"에
가깝다.** 특히 Pinment는:

- 커밋 약 15개, 사실상 1인 저장소 (일부는 AI가 작성)
- 2026-02-25 시작, **마지막 커밋 2026-05-09** — 3개월 넘게 멈춰 있다
- ★3

그래도 포크를 택하는 이유는 별 개수가 아니라 아래 두 가지다.

### 포크가 맞는 진짜 이유

**1. npm 의존성이 거의 없다 — 단, 그게 "외부 통신 없음"이 아니다**

```
dependencies      lz-string          URL 압축용
devDependencies   vite · esbuild · vitest · jsdom     빌드용 — 배포물에 안 실린다
```

> **2026-08-23 정정.** 처음에 이 표만 보고 "실행 의존성 1개, 외부 통신 없음"이라고
> 적었는데 **틀렸다.** `package.json` 은 npm 으로 설치하는 것만 보여준다.
> 코드를 열어 보니 `src/bookmarklet/pdf-export.js` 가 실행 중에 cdnjs 에서 두 개를
> 더 내려받는다.
>
> ```
> https://cdnjs.cloudflare.com/ajax/libs/html2canvas/1.4.1/html2canvas.min.js
> https://cdnjs.cloudflare.com/ajax/libs/jspdf/3.0.3/jspdf.umd.min.js
> ```
>
> 그 파일 주석이 이걸 그대로 말한다 — *"loaded from CDN on demand — **zero npm
> dependencies**"*. **"npm 의존성 0"과 "외부 통신 0"은 다른 말이다.**
> 그리고 원본의 `src/bookmarklet/index.js` 는 이 파일을 실제로 import 한다.
>
> 아래 M0 체크리스트를 "`package.json` 이 아니라 **코드에서** 확인"으로 고친 이유다.

**2. 어려운 두 가지가 이미 풀려 있다**

핀·댓글 UI는 만들면 된다. 진짜 까다로운 건 **선택자 생성**과 **화면 크기가 바뀌었을 때
핀 위치 다시 계산하기**인데 둘 다 이미 있다.

| 어디에 | 무엇이 |
|---|---|
| `src/selector.js` | 선택자 생성 |
| `src/bookmarklet/ui.js` | `calculatePinPosition` · `repositionPin` — 핀 위치 재계산 |
| `src/state.js` | **URL 공유 전용**. 압축·해제·공유주소·JSON 입출력·스키마 검증뿐 |

> **2026-08-23 정정.** 처음에 재계산 로직이 `state.js` 에 있다고 적었는데 **틀렸다.**
> 파일을 열지 않고 이름만 보고 추측한 것이다. 104줄 전부가 URL 공유용이다.
> 그래서 **URL 공유를 안 쓰면 `state.js` 는 통째로 지워도 되고**, 지우면 `lz-string`
> 도 쓸 곳이 없어진다. 반대로 `ui.js` 는 우리가 원하던 핵심이 들어 있어 **통째로
> 지우면 안 된다** — 골라내야 한다.
>
> 단 `state.js` 의 **핀 스키마 검증**(`validateState`)은 살려서 옮긴다.
> 핀은 `s`(선택자) · `ox`/`oy`(요소 안 0~1 상대 위치) · `fx`/`fy`(폴백 절대좌표)로
> 되어 있고, 이게 §10 "선택자를 못 찾으면 좌표로 대체"의 실제 구현이다.

**멈춰 있다는 점은 포크에서는 문제가 아니다.** 가져와서 우리 것으로 만든다.
읽을 수 있을 만큼 작고(파일 몇 개), MIT라 자유롭게 고칠 수 있다.

### 가져오기 전에 반드시 할 것

작은 저장소를 회사 화면에 붙이는 것이다. **코드 전체를 먼저 읽는다.**
"작동하니까 됐다"는 이 문서 §11과 회사 3원칙(AI 과신 지양)에 정면으로 어긋난다.

- [ ] `src/` 통독 — 파일이 몇 개 안 되므로 가능하다
- [ ] **코드에서** 외부로 나가는 통신을 찾는다 — `package.json` 으로는 안 보인다.
      `https://` · `fetch(` · `createElement('script')` 를 전부 훑는다
- [ ] `dist/` 빌드 결과물도 같은 방식으로 훑는다 (원본이 아니라 실제 나가는 물건)
- [ ] MIT 저작권 고지를 포크에 남긴다 — **사내용이어도 의무다**

> 문자열 검색은 **"위험한 이름이 안 나왔다"** 를 보여줄 뿐 **"안전하다"** 를 증명하지
> 않는다. 압축된 코드나 `window['fet'+'ch']` 같은 건 안 걸린다. 우리가 직접 포크해
> 직접 빌드하므로 위험은 낮지만, 결과를 "안전 확인 완료"로 읽으면 안 된다.

### 포크해서 바꿀 것

| 바꿀 것 | 이유 |
|---|---|
| 한국어 UI | 대표·팀원이 쓴다 |
| `[복사]` → Markdown 출력 | Pinment는 URL·JSON만 있다. 슬랙·카톡에 붙여넣으려면 필요 |
| 선택자에 `.st-key-*` 추가 | Streamlit 대시보드가 대상에 있다 |
| `MutationObserver` | Streamlit은 조작할 때마다 화면을 다시 그린다 — 핀이 사라진다 |
| URL 공유를 기본에서 뺀다 | 아래 참조 |
| 민감정보 경고 · 주소의 토큰 제거 | §11 |
| work-cycle 전송 | M2 |

### URL 공유는 기본으로 두지 않는다

Pinment의 핵심 기능은 **댓글 전체를 압축해 URL 하나로 공유**하는 것이다. 편리하지만
**그 URL 안에 회사 화면의 글자가 들어 있다.** 매출액·고객사명이 섞인 주소가
카톡·슬랙·브라우저 기록·서버 로그에 남는다.

기본은 클립보드 복사로 두고, URL 공유는 **끄고 켤 수 있는 선택 기능**으로 내린다.

### 두 곳에서 코드를 가져온다 — 도구는 하나다

Visual Annotator 를 **확장으로 도입하지는 않지만, 그 UI 코드는 가져온다.**
확인해 보니 옮기는 비용이 거의 없다 (2026-08-23 기준):

```
content.js   1,162줄 / 실질 1,004줄 / 46.3 KB
             확장 전용 API(chrome.*) 호출은 8곳뿐
manifest     activeTab · scripting · storage · downloads · <all_urls>
background   chrome.tabs.captureVisibleTab (스크린샷 — 우리는 안 쓴다)
```

**1,000줄 중 확장에 묶인 곳이 8군데다.** 나머지는 그냥 웹 자바스크립트다.

| 가져올 곳 | 무엇을 |
|---|---|
| **Pinment** | 북마클릿 빌드·로더, 상태 구조, 선택자, 리사이즈 재계산, 테스트 |
| **Visual Annotator** | 요소 hover·핀·댓글 팝업, Shadow DOM 툴바, Markdown 출력 |

**Shadow DOM 툴바는 그냥 얻는 이득이다.** §9에서 인스펙터 UI를 `#ui-inspector-root`
안에 두기로 했는데, Shadow DOM 이면 대상 페이지의 CSS 가 우리 UI를 망가뜨릴 수
없다. 직접 만들면 신경 써야 할 부분이 하나 사라진다.

바꿔야 할 8군데는 이렇게 대응한다.

| 확장 API | 북마클릿에서 |
|---|---|
| `chrome.runtime.onMessage` | 북마클릿을 누르면 바로 툴바를 연다 |
| `chrome.runtime.id` | `window.__wcInspector` 같은 전역 키 |
| `chrome.storage.local` | `localStorage` — 출처별로 갈리는 게 오히려 맞다 |
| `chrome.downloads` | 클립보드 또는 `<a download>` |
| `chrome.tabs.captureVisibleTab` | **뺀다** (§7 — 어차피 안 쓰기로 했다) |

**두 라이선스 고지를 모두 남긴다.** 둘 다 MIT라 합칠 수 있지만, 저작권 표시는
각각 보존해야 한다.

### 가져오되 기본으로 켜지 않을 것

Visual Annotator 에는 우리 §11과 충돌하는 기능이 둘 있다.

- **`outerHTML` 복사** — 카드 하나의 HTML 을 통째로 복사한다. 그 안에 매출액,
  고객사명, `data-*` 에 든 내부 ID 가 그대로 들어 있다
- **콘솔 로그 수집** — 토큰·이메일이 로그에 찍혀 있으면 같이 딸려 나간다

둘 다 **끄고 시작한다.** 켤 수 있게는 두되 기본값이 아니다.

> 그리고 복사한 내용을 **외부 AI 도구에 붙여넣는 것은 회사 데이터를 제3자에게
> 보내는 일이다.** 슬랙·카톡(사내)과는 성격이 다르다. 실제로 그렇게 쓰기 전에
> 대표 확인이 필요하다 (`AGENTS.md` §2-3).

### 포크에서 지울 것 — 실물 확인 결과 (2026-08-23)

포크(`ui-inspector`)의 구형 파일 6개를 직접 열어 확인했다. 판단은 이렇다.

| 파일 | 처리 | 근거 |
|---|---|---|
| `src/bookmarklet/pdf-export.js` | **삭제** | cdnjs 2곳 · 동적 `<script>` · `html2canvas(document.body)` · `toDataURL` — §7·§11 과 정면 충돌 |
| `scripts/build-bookmarklet.js` | **삭제** | 외부 로더(`YOUR_BASE_URL/...?v=`)를 만든다. 인라인 방침과 반대 |
| `package.json` 의 `build:bookmarklet` | **삭제** | 위 스크립트를 부르는 입구 |
| `src/state.js` | **삭제** (스키마 검증만 이관) | 104줄 전부 URL 공유용 |
| `lz-string` | **삭제** | `state.js` 가 유일한 사용처 |
| `src/bookmarklet/ui.js` | **골라내기 — 통째로 지우지 말 것** | 아래 |
| `tests/bookmarklet.test.js` · `tests/state.test.js` | 살릴 코드에 맞춰 정리 | 아래 |

**`ui.js` 는 지우는 게 아니라 골라낸다.**

```
살린다   calculatePinPosition  repositionPin      ← 우리가 Pinment 를 고른 이유의 절반
         createPinElement      createPanel
         restorePins           filterAndSortPins
         buildStyles           highlightPinTarget   clearPinHighlight

버린다   createShareModal      ← URL 공유
         createDocsSiteModal   ← Pinment 사이트 링크
         createWelcomeModal    createMobileWarningModal
```

**테스트 숫자를 그대로 믿지 않는다.** 구형 테스트가 정확히 **214개**다
(`bookmarklet.test.js` 154 + `state.test.js` 60). 전체가 248개라면 새 코드를
직접 검증하는 건 **34개뿐**이다. "248개 통과"는 남의 코드가 잘 도는 걸 확인한 쪽에 가깝다.

`ui.js` 에서 살리는 함수들의 테스트는 **같이 살린다.** 지울 함수의 테스트만 지운다.

**파일을 지워도 git 기록에는 남는다.** 공개 저장소면 과거 커밋에서 꺼내 볼 수 있다.
보안 문제는 아니지만(어차피 공개 MIT 코드다), "저장소가 그 기능을 보유하지 않는다"가
아니라 **"현재 코드에는 없다"** 가 정확한 표현이다.

### BugPin 의 AGPL-3.0 은 M2 때 확인이 필요하다

서버·관리화면이 AGPL-3.0이다. 이 라이선스는 **네트워크로 서비스하면 그 소스를
이용자에게 제공**하도록 요구하고, 사내 직원도 이용자에 해당한다. 고쳐 쓰면 그 수정본이
대상이 된다. M2에서 BugPin을 후보로 올릴 때는 **회사 확인을 먼저 받는다.**
위젯(MIT) 만 떼어 쓰는 것은 이 문제가 없다.

## 4. 인스펙터 파일은 어디에 두나

**`work-cycle`에 두면 안 된다.** Cloudflare Access가 호스트 전체를 막고 있어서,
다른 사이트에서 `inspector.js`를 불러오면 스크립트 대신 로그인 화면이 온다.

**`feed-mina.github.io` (GitHub Pages)에 둔다.** 공개 주소라 어디서든 불러와진다.

```
https://feed-mina.github.io/ui-inspector/inspector.js     실제 코드
https://feed-mina.github.io/ui-inspector/                 설치 안내 + 북마클릿 링크
```

북마클릿 본체는 **불러오기만 하는 짧은 코드**로 둔다. 그래야 인스펙터를 고칠 때
파일만 바꾸면 되고, 이미 북마크를 등록한 사람이 다시 등록할 필요가 없다.

```js
javascript:(()=>{const s=document.createElement('script');
s.src='https://feed-mina.github.io/ui-inspector/inspector.js?'+Date.now();
document.body.appendChild(s)})()
```

## 5. 저장 경로 — 여기가 진짜 어려운 부분

A 사이트에서 단 댓글을 work-cycle 서버로 **바로 보낼 수 없다.** 두 겹으로 막힌다.

1. **CORS** — 다른 출처에서 work-cycle API 호출은 브라우저가 차단한다
2. **Cloudflare Access** — API가 로그인 뒤에 있어 인증 없이는 401

북마클릿에 토큰을 심는 방법은 **쓰지 않는다.** 북마크 주소는 평문이고 누구나
열어볼 수 있다. 토큰을 배포하는 것과 같다 (`AGENTS.md` §2-3 위반).

### 해결: 인스펙터는 저장하지 않는다

인스펙터는 **모으기만** 하고, 저장은 **이미 로그인된 work-cycle 탭**이 한다.

```
 [A 사이트]  북마클릿                        [work-cycle 탭]
 ─────────────────────                       ──────────────────────
 요소 클릭 → 댓글 입력
        ↓
 localStorage 에 임시 보관
 (탭을 닫아도 안 날아감)
        ↓
 ┌── 내보내기 두 갈래 ──┐
 │                      │
 [복사]              [work-cycle로 보내기]
   ↓                      ↓
 클립보드            새 탭으로 /review/import 열기
   ↓                      ↓
 슬랙·카톡에         이미 Access 로그인 상태
 붙여넣기            → 같은 출처라 CORS 없음
                     → 그 페이지가 대신 POST
```

돌아가는 것처럼 보이지만, **토큰을 뿌리지 않으면서 저장까지 되는 유일한 경로**다.

## 6. 사용자가 두 종류다

| | 나 | 팀원 · 대표 |
|---|---|---|
| Access 계정 | 있음 | **없을 수 있음** |
| 쓰는 경로 | `[work-cycle로 보내기]` → 바로 저장 | `[복사]` → 슬랙·카톡으로 전달 |
| 내가 할 일 | 없음 | 받은 글을 `/review/import` 에 붙여넣기 |

**대표는 Access 계정이 없을 가능성이 높다.** 그래서 `[복사]` 경로는 선택이 아니라
**필수**다. 이쪽이 오히려 주 경로가 될 수 있다 — 아무것도 설치·가입하지 않아도 된다.

두 경로가 **같은 JSON 형식**을 쓰도록 맞춘다. 붙여넣기와 직접 저장이 같은 코드로 들어간다.

## 7. 무엇을 기록하나

댓글 하나(= 핀 하나)당:

| 필드 | 예 | 왜 필요한가 |
|---|---|---|
| `selector` | `[data-testid="revenue-card"]` | 그 요소를 다시 찾기 |
| `label` | `Card · 매출` | 사람이 목록에서 알아보기 |
| `text` | `매출 2.5억 +14.9%` (앞 60자) | 화면이 바뀌어도 무엇이었는지 |
| `rect` | `{x,y,w,h}` | 나중에 그림으로 다시 표시 |
| `url` | `https://.../dashboard?tab=daily` | 어느 화면인지 |
| `viewport` | `1512x982` | "제 화면에선 안 그런데요" 방지 |
| `ua` | `Chrome 141 / macOS` | 같은 이유 |
| `comment` | `그래프 스티키를 둔다` | 본문 |
| `author` | `팀장` | 누가 남겼나 (직접 입력) |
| `at` | `2026-08-23T14:02+09:00` | |

`viewport`와 `ua`는 빼고 싶어지지만 **넣는다.** 화면 관련 피드백의 상당수가
"창 너비가 달라서" 생기는데, 이 두 값이 없으면 재현에 반나절이 날아간다.

### 스크린샷은 넣지 않는다 (M3까지 보류)

`html2canvas` 류는 무겁고, 외부 이미지·폰트가 있으면 자주 깨진다. 무엇보다
**회사 화면 전체가 이미지로 남는다** — `AGENTS.md` §2-3의 회사 데이터 문제로 직결된다.

좌표(`rect`)만 있으면 나중에 같은 화면에서 위치를 다시 그릴 수 있다. 그걸로 시작한다.

## 8. 요소 경로를 어떻게 잡나

**`.group/card` 같은 디자인용 클래스는 쓰지 않는다.** 디자인을 조금만 손봐도 깨진다.
안 변하는 것부터 순서대로 찾는다.

1. `data-testid` / `data-qa` 등 테스트용 속성 → 있으면 그것만 쓴다
2. `id` → 단, `id="cdk-overlay-3"` 같이 **숫자가 붙어 매번 바뀌는 것은 거른다**
3. `<button aria-label="닫기">` 같은 접근성 속성
4. 위가 전부 없으면 부모를 따라 올라가며 `main > div:nth-child(2) > ...` 경로 계산

4번까지 갔다는 건 그 요소에 붙잡을 표시가 없다는 뜻이다. 이 경우
**`"경로가 불안정함"` 표시를 같이 남긴다.** 나중에 못 찾아도 놀라지 않도록.

> 부수 효과: 4번이 자주 나오는 화면은 `data-testid` 가 부족한 화면이다.
> 인스펙터가 그 목록을 만들어 준다.

## 9. 화면 동작

- 북마클릿을 누르면 커서를 따라 요소에 파란 테두리가 생긴다 (`Esc` 로 종료)
- 클릭하면 그 자리에 번호 핀 + 댓글 입력창
- 오른쪽에 핀 목록. 항목을 누르면 그 요소로 스크롤 + 강조
- 아래에 `[복사]` `[work-cycle로 보내기]` `[전체 지우기]`
- 인스펙터 UI 자체는 `#ui-inspector-root` 안에 넣고, 그 요소는 **클릭 대상에서 제외**한다
  (안 하면 자기 자신에 댓글을 달게 된다)

## 10. 안 되는 것 — 미리 알아둘 것

| 상황 | 결과 | 대응 |
|---|---|---|
| **엄격한 CSP를 쓰는 사이트** | 외부 스크립트 로딩이 막히거나, 북마클릿 실행 자체가 막힌다 | 막히는 종류에 따라 다르다 — 아래 표 참조 |
| `<iframe>` 안의 요소 | 클릭 안 됨 | 브라우저 보안 제약. 프레임 안에서 북마클릿을 다시 눌러야 함 |
| `<canvas>` 로 그린 차트 | 캔버스 전체가 한 요소 | "그래프 안의 7월 15일 막대"는 못 집는다. 댓글로 적어야 함 |
| Shadow DOM 내부 | 경로가 안 잡힘 | M2에서 대응 |
| 스크롤·리사이즈 | 핀 위치가 어긋남 | 좌표를 **요소 기준**으로 저장하고 다시 계산해 그린다 |

**CSP는 실제로 부딪힐 가능성이 높다.** 첫 대상 사이트 3곳에서 M1을 만들자마자
확인하는 것을 완료 기준에 넣는다.

### CSP는 두 가지를 따로 막는다 — 섞어서 생각하면 틀린다

CSP 가 막는 것은 하나가 아니라 둘이고, 대응이 서로 다르다.

| 무엇이 막히나 | 로더 북마클릿 | **인라인 북마클릿** | 확장 |
|---|---|---|---|
| ⓐ 외부 스크립트 로딩 (`script-src`) | ❌ 막힌다 | ✅ 안 불러오니 해당 없음 | ✅ |
| ⓑ 북마클릿 실행 자체 | 브라우저에 달렸다 | 브라우저에 달렸다 | ✅ 항상 된다 |

**흔히 부딪히는 건 ⓐ다.** 그리고 ⓐ는 **인라인 북마클릿으로 실제로 해결된다.**

ⓑ는 다르다. 크롬은 북마클릿을 CSP 에서 빼 주려고 해 왔지만 버전에 따라 막힌
사례가 계속 보고된다
([chromium #40407436](https://issues.chromium.org/issues/40407436),
[vimium #4331](https://github.com/philc/vimium/issues/4331),
[bugzilla 866522](https://bugzilla.mozilla.org/show_bug.cgi?id=866522)).
ⓑ가 걸리면 인라인이든 로더든 똑같이 못 쓴다. 그때는 확장뿐이다.

### 인라인은 되지만 "전체 기능"으로는 안 된다

Pinment 는 전체 스크립트를 인라인에 넣으려다 **Firefox 의 북마크 약 65KB 한도**에
걸려 접었다 (README: *"Inline `javascript:` URI hit Firefox's ~65KB bookmark limit;
a tiny loader fetches the full script from the host site"*). 지금의 로더 방식은 그 결과다.

다만 기능을 줄인 **Lite 빌드**라면 들어간다. Visual Annotator 의 핵심이 압축 전
46.3 KB 이므로, 최소화하면 여유가 있다.

**그래서 빌드를 두 개 만든다.**

```
기본   로더 북마클릿      GitHub Pages 에서 전체 기능을 불러온다. 고칠 때 파일만 교체
보조   인라인 Lite 빌드   외부 로딩 없음. script-src 로 막힌 사이트용. 기능 축소
```

Lite 는 **M1 에 넣지 않는다.** M1 에서 어느 사이트가 실제로 막히는지 확인한 뒤,
막히는 곳이 있을 때만 만든다. 없으면 안 만든다.

### ⓑ까지 막히면: 같은 코드에 확장 껍데기를 씌운다

확장 안의 코드는 **특권 코드**라 페이지의 CSP가 막지 못한다. 이게 확장을 쓰는
거의 유일한 이유다.

**그래도 Visual Annotator를 도구로 도입하지는 않는다.** 도구가 둘이 되면 쓰는 법도
둘이 되고 고칠 곳도 둘이 된다. UI 코드만 가져오고(§3), 껍데기는 우리가 만든다.

```
ui-inspector/
  src/ui.js          핀·댓글·선택자 — 실제 알맹이. 한 벌뿐이다
  src/bookmarklet/   껍데기 ① 로더        평소
  src/inline/        껍데기 ② 인라인 Lite  ⓐ로 막힌 곳
  src/extension/     껍데기 ③ manifest    ⓑ까지 막힌 곳
```

확장은 **스토어에 올리지 않는다.** `chrome://extensions` → 개발자 모드 →
"압축해제된 확장 프로그램을 로드" 로 폴더를 지정하면 끝이다. 심사도 비용도 없다.

**단, 개발자 모드 확장은 공짜가 아니다.**

- 크롬을 켤 때마다 "개발자 모드 확장 프로그램을 사용 중지" 배너가 뜬다
- 회사 정책(그룹정책)으로 막혀 있으면 아예 못 올린다 — 먼저 확인해야 한다
- 고칠 때마다 팀원 각자가 폴더를 새로 받아야 한다 (북마클릿은 파일 하나 교체로 끝)

그래서 **기본은 북마클릿이고, 확장은 막힌 곳 전용 보조**다. M1에는 넣지 않는다.

## 11. 보안·개인정보

`AGENTS.md` §2-3을 그대로 따른다.

- **회사 화면의 글자가 댓글에 딸려 들어온다.** `text` 필드에 매출액·고객사명이
  섞일 수 있다. 저장 위치는 비공개 저장소 또는 D1까지만. **공개 저장소에 올리지 않는다**
- `inspector.js` 는 GitHub Pages(공개)에 두지만, **코드만** 공개다. 수집한 내용은
  브라우저 안에 있다가 work-cycle로만 간다
- 인스펙터는 **입력창의 값을 읽지 않는다.** 비밀번호·검색어가 딸려가는 것을 막는다
- 토큰·키는 북마클릿에 넣지 않는다 (§4)

## 12. 단계

### M0 — Pinment 읽기 (반나절)

**코드를 쓰기 전에 읽는 단계다.** §3의 점검 항목을 끝낸다.
읽어 보니 우리 요구와 안 맞으면 **여기서 접고 직접 만든다** — 그것도 성공한 M0다.

**완료 기준**
- `src/` 를 전부 읽었고, 밖으로 나가는 통신이 없음을 확인했다
- 선택자 규칙(`selector.js`)이 §8의 우선순위와 얼마나 다른지 적었다
- 그대로 쓸 부분 / 고칠 부분 / 버릴 부분을 나눴다

### M1 — 포크 + 최소 수정 (서버 불필요)

`feed-mina/ui-inspector` 로 포크하고 §3 "포크해서 바꿀 것" 중 **앞의 네 개만** 한다:
한국어 UI · `[복사]` Markdown · `.st-key-*` · URL 공유를 기본에서 빼기.
`feed-mina.github.io/ui-inspector/` 에 배포.

`MutationObserver` 와 민감정보 경고는 M1에 넣지 않는다. 실제로 써 보고
정말 필요한지 확인한 뒤에 넣는다.

**완료 기준**
- work-cycle · feed-mina.github.io · Streamlit 대시보드 **세 곳에서 실제로 동작**한다
- 탭을 닫았다 열어도 핀이 남아 있다
- `[복사]` 결과를 슬랙에 붙여넣으면 표로 읽힌다
- CSP로 막히는 사이트가 있으면 어디인지 기록했다
- MIT 저작권 고지가 포크에 남아 있다

### M2 — work-cycle에 쌓기

`/review` 화면, `ui_feedback` 테이블, `/review/import`(붙여넣기 + 새 탭 수신),
목록·상태(열림/처리됨/보류), GitHub 이슈로 넘기기 버튼.

**완료 기준**
- 대표가 `[복사]`한 글을 붙여넣으면 핀이 그대로 복원된다
- 이슈로 넘긴 항목에 이슈 번호가 남는다

### M3 — 되짚어보기

저장된 핀을 그 화면에서 다시 표시(요소를 못 찾으면 좌표로 대체 + "요소 없음" 표시),
스크린샷 첨부 여부 재검토.
