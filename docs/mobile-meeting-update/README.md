# 모바일 화면과 개인 회의록 보관

휴대폰에서 제목을 읽고 회의 내용을 사이트 안에서 확인하려는 사용자를 위한 변경이다. 기존 회사 사이클 6단계, 체크리스트 문구, OAuth 갱신, 기록 저장 경로, 자동 알림 시간은 유지한다.

## 달라진 화면

- 모든 기존 화면에 모바일 하단 메뉴: 오늘, 기록, 작업, 더보기. work-cycle에는 프로젝트 페이지가 없으므로 작업은 기존 칸반을 연다.
- 회의록: 제목·날짜·읽음 상태를 카드로 구분하고 검색/안 읽음 필터 제공. 상세는 요약·원문·할 일·보관 이력이며 목록 복귀 시 필터 유지. 원문은 저장된 본문 그대로의 텍스트이며 외부 링크만 있는 회의는 원본 링크를 제공한다. 생성된 요약을 원 녹취로 오인하지 않도록 별도 원문 보존은 기존 저장 기능을 따른다.
- 일정: 모바일 주간 화면을 날짜별 한 열 목록으로 변경. 기존 월간 달력과 도넛은 유지한다.
- 칸반: 카드별 상태 선택으로 끌기 없이 원하는 상태로 이동. 기존 완료/되돌리기 유지.
- 주간보고: 모바일 날짜별 접기 목록과 수정 대화상자. 실제 보고서 수정 API와 연결한다. 데스크톱 엑셀 양식 유지.
- 개인 준비 현황: 다음 행동을 먼저 표시하고 결과 표를 모바일 카드로 읽는다.
- 더보기: 일정·보고·현황·알림 설정·GitHub 연결 진입 제공.

## 개인 회의록 ME 보관

`migrations/0025_meeting_history.sql`을 운영 D1에 적용해야 한다. 운영 DB에는 이 작업에서 적용하지 않았다. 기존 `VAULT_HISTORY_EMAIL`, `GITHUB_TOKEN_VAULT`, `VAULT_REPO` 설정을 쓴다. 지정한 단일 소유자의 개인 모드 개인 회의만 허용하고, 버튼을 누른 회의만 보관한다. 회사 회의와 다른 계정 회의는 제외한다.

기본 경로는 `history/meetings/YYYY/MM/YYYY-MM-DD_work-cycle-meeting-ID.md`. 첫 보관 후 제목·날짜를 바꾸어도 같은 경로를 사용한다. 동일 내용은 추가 커밋하지 않는다. 이전에 보관한 원격 파일 해시를 비교하여 사람이 GitHub에서 수정한 경우 덮어쓰지 않고 충돌을 표시한다. DB 저장과 ME 보관 상태는 별개이며 원격 보관 실패로 앱 기록을 삭제하지 않는다. `01-History`와 `history`를 기존 개인 볼트 읽기 기본 허용 폴더에 추가한다. 기존 폴더 이름을 변경하거나 파일을 옮기지 않았다.

## 검증

- `npx tsc --noEmit` 및 public의 전체 인라인/공용 JavaScript 문법 검사.
- 기존 개인 모드 153 API 검사, 기존 일일 기록 28 검사: 로컬 D1 + 가짜 GitHub, 외부 발송 없음.
- 회의 보관 테스트: 소유권/모드, 스키마 미적용, 동일 내용, 날짜 수정 후 같은 경로, 원격 충돌, 실패 격리와 이력 확인.
- 실제 Wrangler 로컬 브라우저: 개인 홈·일정·회의·칸반·현황·보고·더보기 개인/회사 모드 각각 420/1280px 가로 넘침 0. 회의 상세 탭과 목록 복귀, 모바일 보고서 저장 대화상자 실제 조작, JavaScript 오류 없음.
- 공개 데모는 별도 `portfolio/`와 `wrangler.portfolio.toml`. 운영 DB/OAuth/알림에 연결하지 않는 별도 배포를 준비한다. 운영 로그인 정책 변경이나 별도 공개 도메인 배포는 수행하지 않는다.

브라우저 검사: `CHROMIUM_PATH=<브라우저 경로> node tests/mobile-browser.test.cjs`. 로컬 Worker 18788에만 실행하며 허구 테스트 기록을 작성하므로 운영 주소로 바꾸지 않는다. 회사 화면은 `TEST_MODE=company`로 검사한다. 테스트용 한글 폰트 CSS는 선택적으로 `TEST_FONT_CSS`로 전달할 수 있다.
