## 3. 최근 3개 기능의 핵심 (이어받을 때 알아야 할 것)

### 3-1. 주간업무보고 (`src/report.ts` · `src/xlsx.ts`)

- 회사 양식 `주간업무보고_양식용 2.xlsx`를 **서버에서 그대로 재현**합니다.
  외부 라이브러리 없이 CRC32 + 무압축 ZIP + OOXML을 직접 씁니다 (`xlsx.ts`).
- **주차 기준은 "그 달의 첫 월요일이 있는 주가 1주차"** (2026-08-22 사용자 확정).
  2026년 월요일 52개 전수 검증 통과. 원본 양식 예시(6/29~7/3 = 6월 5주차)와도 일치.
- 자동 집계는 **초안**입니다. 화면에서 고친 칸만 `report_overrides`에 고정되고
  나머지는 계속 자동 갱신됩니다. 이 구조를 깨지 마세요.
- 금요일 13:00 KST에 카카오로 "초안 준비됨" 알림. cron 슬롯 `{ hhmm: 1300, dow: 5 }`.
- ⚠️ 금요일 **오후** 작업은 초안에 안 들어갑니다. 퇴근 전 화면에서 보정하는 흐름 전제.
- 개인용(사용 화면 = 개인용)은 화면·xlsx가 **월~일 7행**(`collect(db, email, mon, 7)`, 2026-09-27 사용자 결정). 회사용은 5행 양식 그대로(수정 전후 xlsx 바이트 동일 확인). 주말(토·일) cron 은 **개인용 리마인드만** 보낸다(`reminders.ts slotAt` → `runSlot(..., { personalOnly })`), 회사용 알림·금요일 보고는 평일 그대로.

상세: [`주간업무보고-자동생성-설계.md`](weekly-report-design.md)

### 3-2. 회의 중 실시간 메모 (`/meetings` 첫 탭)

- 트리형 아웃라이너. `Enter` 새 줄 / `Tab`·`Shift+Tab` 들여쓰기 / `Ctrl+1~4` 마크
- 마크: ★중요 ◆결정 ☑할일 ❓확인필요 → 산출물에서 각각 별도 섹션이 됩니다
- ☑할일 줄에만 **담당·기한** 칸이 나타나고, 칸반으로 전송하면
  기한 있는 건 `즉시처리`, 없는 건 `전략적계획`으로 들어갑니다
- 1.2초 디바운스 자동 저장. `outline`은 JSON 배열 `[{d,m,t,who,due}]`
- 서버 `cleanOutline()`이 깊이(0~5)·마크 화이트리스트·길이를 강제합니다

### 3-3. 산출물 포맷 (`src/notedoc.ts`)

**제목 바로 아래 "이 회의로 정하려는 것"이 항상 옵니다.** 비어 있으면
_"목적이 적히지 않았습니다 — 다음 회의에는 먼저 적어주세요"_ 가 대신 찍힙니다.
"목적을 알 수 있게 상세히"라는 요구를 사람 습관이 아니라 **포맷으로 강제**한 부분이라, 지워지면 안 됩니다.

- `?fmt=md` / `?fmt=html` 내려받기, `?fmt=html&inline=1` 새 탭 → 브라우저 인쇄로 PDF
- 서버 PDF 생성은 Workers에서 무거워 넣지 않았습니다

## 5. 알림 시간표 (`SLOTS` in `src/index.ts`)

cron 표현식은 **1개**: `0,25,30,40 23,1,3,4,8 * * *` (무료 플랜 트리거 3개 한도 회피)
코드에서 KST 시각을 보고 갈라 보냅니다. 주말은 자동 제외.

| KST | 종류 |
|---|---|
| 08:25 | 아침 브리핑 (구글 캘린더 일정 포함) |
| 10:00 | 체크리스트 · 하루 시작 |
| 12:30 | 체크리스트 · 작업 중 / AI 사용 |
| **13:00 (금요일만)** | 주간업무보고 초안 준비됨 |
| 17:00 | 체크리스트 · 제출 전 |
| 17:40 | 저녁 점검 |

체크리스트 알림은 **아직 안 누른 항목만** 보내고, 다 눌렀으면 발송하지 않습니다.
