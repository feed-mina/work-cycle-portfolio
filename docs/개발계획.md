## 0. 먼저 짚어야 할 것

`AGENTS.md` 첫 문단이 이 프로젝트의 기준입니다.

> 기능을 늘리는 것보다 **이 3가지가 화면에서 실제로 강제되는가**가 우선입니다.

그런데 최근 작업은 대부분 **새 기능 추가**였습니다.

| 최근에 한 것 | 성격 |
|---|---|
| 주간보고 AI 문장 다듬기 | 새 기능 |
| 회의 메모 → 요구사항 연결 | 새 기능 |
| 옵시디언 볼트에서 회의록 읽기 | 새 기능 |
| 바탕화면 배너 | 새 도구 |
| UI 인스펙터 설계 | 새 도구 계획 |

기능이 늘어난 만큼 **매일 실제로 쓴 기록**은 늘지 않았습니다.
그래서 이 계획의 첫 단계는 "만들기"가 아니라 "쓰기"입니다.

## 1. 이 계획을 어떻게 쓰나

- **한 번에 한 줄기만.** 동시에 두 개를 벌이면 둘 다 반쯤 된 채로 남습니다
- **완료 기준이 없는 항목은 착수하지 않습니다.** "좋아지면 끝"은 안 끝납니다
- 순서를 바꾸고 싶어지면 기준은 하나 — **"3원칙을 실제로 지키는 데 더 가까운가?"**

## 2. 지금

### 2-1. 매일 쓰기 (우선순위 1위)

하루 사이클 6단계를 실제로 돌립니다. 어색한 지점이 나오면 **고치지 말고 먼저 적습니다.**
바로 고치면 "무엇이 불편했는지"가 기록에 안 남습니다.

**완료 기준**
- 최소 5일치 기록이 D1 에 쌓여 있다
- 불편한 지점 목록이 있다 (칸반 `즉시처리` 또는 회고의 `tomorrow_prompt`)
- 그 중 실제로 고친 것과 안 고친 것이 구분돼 있다

### 2-2. 구글 앱 게시 (사람이 해야 함)

**막히면 이미 만든 기능이 죽습니다.** 새 기능이 아니라 그걸 막는 일입니다.

```
7일마다:  캘린더 연결 끊김 → 화상회의 링크 생성 실패 → 카카오 공유 버튼 미표시
```

**남은 절차**
1. `feed-mina.github.io` 에 개인정보처리방침 페이지 올리기 (내용 전달 완료)
2. GCP 브랜딩 화면에서 앱 이름·지원 이메일·홈페이지·개인정보처리방침 URL 채우기
3. 앱 게시 → **work-cycle 에서 구글 캘린더 다시 연결**
   (이걸 빼면 기존 토큰이 그대로 만료된다)

**완료 기준**: 게시 8일 뒤에도 화상회의 만들기가 된다

### 2-3. D1 백업 (반나절)

**지금 백업이 전혀 없습니다.** 매일 기록을 쌓고 있는데 사고가 나면 전부 사라집니다.
쌓는 것보다 지키는 게 먼저입니다.

크게 만들지 않습니다.

- 주 1회 cron 으로 전체 테이블을 JSON 으로 덤프해 R2 에 저장
- 파일명에 날짜, 4주치 보관

**완료 기준**
- R2 에 파일이 실제로 생겼다
- **복원을 한 번 해봤다** — 만들어만 두고 복원해 본 적 없는 백업은 백업이 아니다

> `AGENTS.md` §2-5: `seed/seed.sql` 을 운영 DB 에 다시 돌리지 않는다.
> 맨 위 `DELETE FROM checklist_items` 때문에 기록이 날아간다. 복원 시험은 **로컬 D1** 에서.

## 3. 다음 — UI 인스펙터

설계는 [`ui-inspector-design.md`](ui-inspector-design.md) 에 있습니다. 요약만 적습니다.

| | 무엇 | 크기 | 완료 기준 |
|---|---|---|---|
| **M0** | Pinment + Visual Annotator 코드 통독 | 반나절 | 외부 통신 없음 확인. 쓸 것/고칠 것/버릴 것 분류. **안 맞으면 여기서 접는 것도 성공** |
| **M1** | 포크 + 최소 수정 4가지 | 2~3일 | 세 사이트에서 동작. `[복사]` 결과가 슬랙에서 표로 읽힘. MIT 고지 보존 |
| **M2** | work-cycle 에 쌓기 | 3~4일 | 대표가 복사한 글을 붙여넣으면 핀이 복원됨 |
| **M3** | 되짚어보기 | 미정 | M2 를 써 본 뒤 판단 |

**M1 과 M2 사이에 반드시 실사용 기간을 둡니다.** M1 을 며칠 써 보지 않고 M2 로
넘어가면, 아무도 안 쓸 저장 기능을 만들게 됩니다.

M2 착수 전에 확인할 것:
- 회사 PC 에서 개발자 모드 확장이 그룹정책으로 막혀 있는지 (막혀 있으면 CSP ⓑ 대응 경로가 없음)
- 복사한 내용을 외부 AI 도구에 붙여넣어도 되는지 (대표 확인 · `AGENTS.md` §2-3)

## 5. 사람만 풀 수 있는 것

코드로는 못 푸는 항목입니다. 막혀 있는 동안 관련 기능이 동작하지 않습니다.

| 항목 | 막힌 이유 | 안 풀면 |
|---|---|---|
| **구글 앱 게시** | 테스트 모드라 refresh token 7일 만료 | 화상회의·카카오 공유가 주마다 끊김 |
| 회의록 원문 저장 | 대표 승인 필요 | `body_mode=link_only` 유지 — AI 요약 품질 제한 |
| 외부 AI 에 회사 화면 붙여넣기 | 제3자 전송이라 확인 필요 | 인스펙터 M2 의 활용 폭이 줄어듦 |
| 확장 프로그램 설치 정책 | 회사 그룹정책 확인 필요 | CSP 강한 사이트에서 인스펙터 사용 불가 |
| 카카오 비즈 앱 | 전환 불가로 확인됨 | 카카오 **로그인** 불가. 알림은 정상이라 영향 작음 |

## 6. 주간 점검

금요일 회고(`/` 화면 ⑥) 때 이 문서를 열고 세 가지만 확인합니다.

1. 이번 주에 **실제로 쓴 날**이 며칠인가 (기능을 몇 개 만들었나가 아니라)
2. 2절 완료 기준 중 채운 것이 있나
3. 순서를 바꿔야 하나 — 기준은 **"3원칙을 실제로 지키는 데 더 가까운가"** 하나뿐

## 7. 이 계획을 세우며 정한 것

- **새 기능보다 실사용이 먼저다.** 예외는 백업 하나이고, 그것도 기록을 지키기 위한 것
- 인스펙터는 설계까지만. 구현은 2절이 자리 잡은 뒤
- 위젯은 배너를 한 달 써 본 뒤 판단. 안 만들 수도 있다
- 백업은 **복원 시험까지 해야** 완료다
